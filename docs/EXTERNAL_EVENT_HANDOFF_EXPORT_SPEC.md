# External Event Handoff Export Spec

This document defines the exact JSON artifact emitted by this repo's pipeline
when it exports community events for the external handoff workflow.

It is the producer-side spec for:

- [EXTERNAL_EVENT_HANDOFF_CONTRACT](EXTERNAL_EVENT_HANDOFF_CONTRACT.md)
- [PLAY_PERDIDO_API_POSTING_GUIDE](PLAY_PERDIDO_API_POSTING_GUIDE.md)

This export replaces the old direct WordPress/EventON publish step in the main
pipeline flow.

## Purpose

The pipeline in this repo is responsible for:

1. scraping and collecting source events
2. running ML classification
3. applying deterministic filters
4. enriching records with basic normalized fields
5. exporting source facts into a handoff bundle

The pipeline is not responsible for:

- final editorial rewrite
- final public taxonomy mapping
- structured location creation beyond candidate location hints
- final publish to EventON

This export should be treated as a source-facts bundle for the downstream
importer/editorial workflow.

## Output File

The exporter writes a JSON file to:

- `output/pipeline/external_event_handoff_<timestamp>.json`

Current implementation:

- exporter module: [external_handoff_export.py](../scripts/pipeline/external_handoff_export.py)
- pipeline wiring: [automated_pipeline.py](../scripts/pipeline/automated_pipeline.py)

## Top-Level Bundle Shape

The emitted file is a JSON object with:

- `bundle_id`
- `source_system`
- `built_at`
- `events`
- `locations`
- `notes`

Example:

```json
{
  "bundle_id": "envision_perdido_pipeline-20260506_154500",
  "source_system": "envision_perdido_pipeline",
  "built_at": "2026-05-06T15:45:00Z",
  "events": [],
  "locations": [],
  "notes": []
}
```

## Top-Level Fields

### `bundle_id`

Producer-generated identifier for the export bundle.

Current behavior:

- generated automatically when not provided
- format: `envision_perdido_pipeline-YYYYMMDD_HHMMSS`

### `source_system`

Bundle-level producer identifier.

Current default:

- `envision_perdido_pipeline`

Event-level `source_system` may differ when an individual record came from a
specific scraper source.

### `built_at`

UTC timestamp for when the export bundle was created.

Current format:

- ISO 8601 with `Z`
- example: `2026-05-06T15:45:00Z`

### `events`

Array of exported source-event records.

These are the primary payload.

### `locations`

Array of candidate structured locations that were resolvable from the local
venue registry.

These are not guaranteed to be fully publish-ready location records.

### `notes`

Bundle-level QA and completeness notes generated by the exporter.

Current note types include:

- count of events missing `summary_raw`
- count of events with unresolved location text and no proposed location match
- count of events carrying explicit review notes
- count of possible duplicate groups flagged for downstream review

## Event Field Semantics

### `external_id`

Stable source-side event identifier.

Current mapping priority:

1. `external_id`
2. `uid`
3. `id`
4. generated SHA1-based fallback from source/title/url/start

Producer note:

- generated fallback IDs are stable only as long as the contributing source
  facts do not change materially

### `source_system`

Per-event source identifier.

Current mapping:

- event `source` when available
- fallback: `envision_perdido_pipeline`

Examples:

- `perdido_chamber`
- `wren_haven`

### `source_url`

Best source URL for the event.

Current mapping:

- event `url`

This may be empty for some weak source records and should be treated as a QA
risk downstream.

### `source_type`

Loose source-side event type classification.

Current mapping:

- event `category` when present
- fallback: `community_event`

This is not the final public taxonomy.

### `schedule_mode`

Timing mode for the event.

Current mapping:

- `recurring` when a non-empty recurrence object is present
- `single_instance` when a start time exists and recurrence is empty
- `unspecified` when timing data is too weak

### `title_raw`

Raw provisional title from the source pipeline.

Current mapping:

- event `title`

This is not guaranteed to be publish-ready copy.

### `title_cleaned`

Light cleanup version of `title_raw`.

Current behavior:

- collapses obvious spacing glitches
- removes low-risk duplicated words
- preserves the overall source phrasing

This is intentionally conservative and should not be treated as editorial copy.

### `summary_raw`

Short provisional summary when available.

Current mapping:

- event `summary`

Current known limitation:

- most records do not yet have a strong summary field, so this is often empty

### `description_raw`

Best available source description.

Current mapping:

- event `description`

This may already include some optional LLM cleanup from the current pipeline,
but it should still be treated as provisional copy.

### `location_name_raw`

Best inferred venue/location name extracted from the raw location string.

### `location_address_raw`

Best inferred street-address portion extracted from the raw location string.

### `location_hint`

Raw source-side venue or location string.

Current mapping:

- event `location`

### `location_external_id`

Authoritative source-side location ID when the source system already provides
one.

Current mapping:

- event `location_external_id`

Important:

- this field is usually empty in the current scraper set

### `suggested_location_external_id`

Tentative exporter-side proposal based on local venue resolution heuristics.

Current mapping:

- event `venue_id` when the local venue registry produced a likely match

Important:

- this is not authoritative
- downstream systems must verify it against the canonical location catalog

### `location_match_confidence`

Exporter-side confidence in `suggested_location_external_id`.

### `location_match_basis`

Short explanation of why the exporter proposed a location match.

Examples:

- `exact_location_name_match`
- `canonical_name_contained_in_location`
- `alias_or_partial_location_match`

### `location_candidates`

Array of tentative location proposals with confidence and basis metadata.

### `start_at`

Start timestamp for the event.

Current mapping:

- event `start`
- exported as timezone-aware ISO string
- naive input times are localized to `America/Chicago`

### `end_at`

End timestamp for the event.

Current mapping:

- event `end`
- exported as timezone-aware ISO string when available

### `timezone`

Canonical timezone for exported event times.

Current default:

- `America/Chicago`

### `recurrence`

Structured recurrence object when the source provided one.

Current behavior:

- preserves dict recurrence payloads
- attempts to parse JSON strings into dicts
- falls back to `{}` when recurrence is absent or unusable

Current known limitation:

- most current sources do not provide structured recurrence

### `schedule_basis`

Describes which source fields supported the schedule extraction.

Examples:

- `start_and_end_fields`
- `start_field_only`
- `recurrence_field`
- `no_usable_schedule_fields`

### `image_candidates`

Candidate source images for downstream editorial selection.

Current behavior:

- first supported image field wins
- accepted source fields:
  - `image_url`
  - `image_path`
  - `image`
- emitted candidate shape:
  - `type`
  - `value`
  - `role`

Current role behavior:

- first candidate is emitted as `hero`

### `cost_raw`

Best available source-side cost text.

Current mapping priority:

1. `cost_text`
2. `cost`

### `cost_evidence`

Best source-side text snippet supporting the cost interpretation.

### `is_free`

Normalized free/paid boolean when detectable.

Current mapping:

- derived from the normalizer's paid/free detection

Possible values:

- `true`
- `false`
- `null`

Current producer rule:

- `false` is only emitted when the exporter sees direct evidence of ticket,
  admission, registration, entry, cover, or fee cost, or when an explicit
  source cost field exists
- promotional prices like drink specials or discounts do not imply paid
  admission

### `pricing_confidence`

Exporter-side confidence in the paid/free interpretation.

### `tags_raw`

Raw internal tags inferred by this repo.

Current mapping:

- event `tags`

Important:

- these are internal pipeline tags
- they are not the final public site categories or discovery tags
- downstream systems must remap them into contract-approved taxonomy

### `editorial_status`

Current editorial state of the copy.

Current value:

- `raw`

### `needs_editorial_rewrite`

Boolean flag indicating the copy is still provisional and should go through
downstream editorial rewrite.

### `extraction_confidence`

Exporter-side confidence in the completeness of the extracted source facts.

### `review_notes`

Exporter-generated review guidance for downstream editorial handling.

Current note triggers include:

- model flagged `needs_review`
- record carried a `filter_reason`
- location is unresolved and only present as raw text
- no source summary is available

### `confidence`

ML confidence score when available.

Current mapping:

- event `confidence`

This is a model signal, not a publish decision.

### `decision_score`

Raw signed model decision score when available.

Current mapping:

- event `decision_score`

This is for diagnostics and analysis only.

### `possible_duplicate_group`

Optional duplicate-cluster ID for events that appear to describe the same
underlying event.

### `duplicate_candidate_of`

Optional anchor event ID when a record is considered a likely duplicate of a
primary event in the same duplicate group.

### `duplicate_confidence`

Exporter-side confidence in the duplicate clustering signal.

### `duplicate_basis`

Short explanation of why duplicate clustering was triggered.

### `raw_payload`

JSON-safe echo of the source row after pipeline enrichment.

Current behavior:

- includes non-empty source fields from the event row
- preserves enriched fields like `venue_id`, `tags`, `paid_status`, and
  `needs_review`

Use this for debugging and reconciliation, not as a public content contract.

## Location Record Shape

When an event is matched to a known venue in the local registry, the exporter
also emits a candidate location record in `locations[]`.

Current location fields:

- `external_id`
- `source_system`
- `name`
- `address`
- `city`
- `state`
- `raw_hint`

Current mapping source:

- [venue_registry.py](../scripts/tooling/venue_registry.py)

Known limitation:

- many venue registry entries only have name/city/state today
- this is useful as a resolver hint, but not yet a full publish-grade location
  catalog

## Current Producer Rules

The current exporter makes these deliberate choices:

1. preserve source facts instead of inventing polished fields
2. preserve internal tags as raw inputs rather than pretending they are final
   public taxonomy
3. surface unresolved locations explicitly
4. include review notes rather than silently dropping weak data
5. emit tentative location and duplicate proposals without treating them as
   authoritative
6. stop before any WordPress/EventON publishing step

## Known Outliers

Downstream consumers should expect these gaps:

- `summary_raw` is often empty
- organizer fields are rarely populated
- structured recurrence is sparse
- some events still have only text-based locations and no strong location match
  proposal
- internal `tags_raw` require deterministic remapping
- public copy fields like `summary`, `body`, `audience_tags`,
  `discovery_tags`, and `perdido_fit` are not produced here

These are not bugs in the exporter. They reflect the current separation of
responsibilities in the contract.

## Consumer Guidance

If another importer or Codex session consumes this file, it should:

1. validate required source facts first
2. treat `*_raw` fields as provisional copy
3. treat `suggested_location_external_id` and `location_candidates` as proposals,
   not authoritative matches
4. map `tags_raw` into the destination contract's controlled taxonomy
5. use `possible_duplicate_group` and `duplicate_basis` as review signals
6. resolve `location_external_id`/`suggested_location_external_id` or promote
   `location_hint` into review
7. generate final editorial copy and publish decisions downstream

Do not post this bundle directly to EventON without a second normalization and
QA layer.
